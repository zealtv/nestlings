# Design repository bootstrap from a nest

Specify and prototype the workflow for starting a new repository with Nestlings
alone and adding project furniture only when incoming material earns it.

Cover at least:

- installing a nest into an otherwise empty repository;
- placing an establishment request and initial materials in `in/`;
- tending that request into whichever optional primitives are justified;
- preserving a short result or receipt in `out/`;
- the minimal agent-file pointer needed to discover `.nest/tend.md` and `.nest/in/`.

Do not make `install.sh` install sibling primitives. If convenience automation is
warranted, keep it outside the Nestlings protocol boundary and make each added
primitive explicit and independently inspectable.

Done when the complete path can be demonstrated in a temporary fresh repository
and is documented from the user's point of view.
