# Design capture-now, batch-later items

Define and document the simplest useful item shape for dropping material into a
repository now with a note about how it should be handled later. Exercise both a
single-file item and a directory envelope such as:

```text
.nest/in/review-source/
  request.md
  attachments/
```

Reconcile this with the present claim that `in/` is “work ready now” and with
the default `tend.md` instruction that work which cannot finish in one tend cycle
should be dropped or escalated. Batch waiting in `in/` must not be confused with
an abandoned, failed, scheduled, or actively claimed item.

Avoid mandatory metadata unless a real ambiguity cannot be solved by filenames,
ordinary prose, or the existing directory shape.

Done when a person can capture mixed material quickly, leave intent beside it,
and later tend the inbox without a private convention.
